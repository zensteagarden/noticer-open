# Security

This is an early public verifier, not a security certification or hosted-service release. Use caller-controlled packet directories and bounded workloads. Full nested schema validation, receipt/trust input limits and broader resource-exhaustion testing remain unfinished. Keep private keys, credentials and customer data out of fixtures and reports.

For a public GitHub repository, enable **Private vulnerability reporting** before inviting broad use. Once enabled, reporters should use the repository's **Security → Report a vulnerability** flow so sensitive details are not posted in a public issue.

If private reporting is unavailable, do not publish exploit details, credentials or customer evidence. Open only a non-sensitive issue asking the maintainer for a secure reporting channel.

A useful report identifies the source artifact/version, runtime, a minimal synthetic reproducer, expected versus observed behavior, and any safe workaround. Do not test other people's systems without authorization. Scope security claims to the checks actually executed.
